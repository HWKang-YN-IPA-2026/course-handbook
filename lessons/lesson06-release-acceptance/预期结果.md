# 第06次课教师演示预期结果

## 一、环境检查

```bash
./verify_environment.sh
```

预期依次显示`psql`、`createdb`、`java`和`mvn`的实际路径，`pg_isready`报告本机5432端口接受连接，末行是：

```text
ENVIRONMENT READY
```

## 二、完整发布验收

```bash
createdb -h localhost lesson06_acceptance
./run_acceptance.sh lesson06_acceptance
```

### 数据库验收

AC-01至AC-10均应输出`PASS`。检查范围包括核心表、同课程同学期唯一约束、校际共享、协议有效期、历史成绩、重修策略、重复拒绝、失败回滚和关键索引。

### JDBC验收

第05次课集成检查应输出以下稳定结果码：

```text
AC-404 PASS: RETAKE_NOT_ALLOWED
AC-405 PASS: ENROLLED
AC-406 PASS: DUPLICATE_TERM_COURSE
AC-407 PASS: NO_ACTIVE_AGREEMENT
AC-408 PASS: ENROLLED
AC-409 PASS: EXTERNAL_QUOTA_FULL
AC-410 PASS: two concurrent requests produce one winner
AC-411 PASS: database contains exactly one concurrent winner
ALL LESSON-05 CHECKS PASSED
AC-11 PASS: JDBC transaction and concurrent last-seat checks passed
```

并发场景中具体哪一个请求成功不固定，但成功数必须恰好为1。

### 可靠性和安全演示

预期包含：

```text
UNSAFE_SQL=SELECT * FROM student WHERE student_id='S002' OR '1'='1'
SAFE_SQL=SELECT * FROM student WHERE student_id=?
BOUND_VALUE=S002' OR '1'='1
RESOURCE_CLOSED
EXCEPTION_HANDLED=simulated failure
RG-01 PASS: exception, resource release and injection contrast demonstrated
RG-02 PASS: credentials, generated files and parameterized SQL checked
RELEASE SECURITY CHECK PASSED
```

这里的`UNSAFE_SQL`用于展示字符串拼接如何改变SQL结构；程序不会执行该语句。`SAFE_SQL`保持SQL结构固定，恶意文本只作为参数值。

### 最终结论

全部检查通过时，末行必须是：

```text
LESSON-06 RELEASE ACCEPTANCE PASSED (AC-01..AC-11)
```

## 三、课堂现场变化

AC-12没有固定预期答案。教师公布变化后，小组应保存新验收条件、修改差分、RC2提交哈希以及再次运行全部检查的结果。AC-12没有修改的v0.4规则仍应保持原结果。

## 四、清理

演示结束后删除专用数据库：

```bash
dropdb -h localhost lesson06_acceptance
```
