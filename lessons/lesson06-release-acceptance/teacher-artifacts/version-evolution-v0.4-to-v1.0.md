# 选课系统v0.4到v1.0发布演化证据

## v0.4状态

v0.4已经实现历史成绩、重修、共享资格、配额、同期重复、事务回滚和最后一席并发控制，并通过第05次课集成检查。

## v0.4仍缺少的发布证据

- 尚未以固定提交作为统一验收对象。
- 尚未证明第三方仅凭README能从空库复现。
- 尚未系统检查异常、资源、SQL注入和凭据保护。
- 尚未完成跨组复验和岗位证据抽查。
- 尚未证明现场变化后旧功能仍然有效。
- 尚未形成发布说明、已知限制和不可移动标签。

## v1.0发布承诺

v1.0是实践一首次满足既定功能范围、空库复现、功能验收、可靠性与安全、追溯、独立复核和版本固定要求的稳定基线。

## 发布门

| 发布门 | 判定条件 | 证据 |
|---|---|---|
| G1 范围冻结 | 功能范围和保持不变项明确 | 候选版本记录 |
| G2 空库复现 | 第三方能够重放v0.2→v0.4 | 完整日志 |
| G3 功能验收 | AC-01至AC-11全部通过 | 自动验收输出 |
| G4 可靠性与安全 | 异常、资源、注入和凭据检查通过 | RG-01、RG-02 |
| G5 追溯完整 | 需求到课堂证据没有断链 | 追溯矩阵 |
| G6 独立复核 | 复核组按README得到相同结论 | 同伴验收记录 |
| G7 变化承受能力 | AC-12通过且旧用例继续通过 | RC2与回归日志 |
| G8 发布固定 | 发布检查通过，标签指向最终提交 | 发布决策和标签 |

## 候选版本流转

```text
v0.4功能基线
→ 冻结RC1提交
→ AC-01至AC-11与发布门检查
→ 同伴复验
→ AC-12现场变化
→ 新候选提交RC2
→ AC-12与全量回归
→ practice-1-v1.0
```

RC1和RC2记录为提交哈希，不强制创建额外标签。

## 保持不变

- 延续第05次课的数据模型、业务主键和规则优先级。
- 延续历史重修、共享协议、配额和同期唯一约束。
- 延续事务回滚和最后一席并发控制。
- AC-12未明确修改的规则必须保持原结果。

## 版本结论

v0.4到v1.0不是单纯增加功能，而是从“功能实现基线”升级为“可复现、可复核、可交付、可固定”的首次稳定发布。
