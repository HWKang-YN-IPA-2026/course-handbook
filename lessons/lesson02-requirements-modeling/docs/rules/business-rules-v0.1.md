# 业务规则 v0.1

## 判断顺序

系统按下列顺序判断。前一条失败时立即返回，不再执行后续规则。

| 编号 | 可判断的规则 | 失败代码 | 来源 |
| --- | --- | --- | --- |
| BR-001 | 学生存在且状态为ACTIVE | `STUDENT_INACTIVE` | UC-001步骤2 |
| BR-002 | 课程存在且状态为OPEN | `COURSE_CLOSED` | UC-001步骤3 |
| BR-004 | 不存在相同学生和课程的有效选课记录 | `DUPLICATE_ENROLLMENT` | UC-001步骤4 |
| BR-003 | 当前已选人数小于课程容量 | `COURSE_FULL` | DEC-001、UC-001步骤5 |

## 决策表

“—”表示前面的条件已经足以决定结果，后续条件不再判断。

| 学生正常 | 课程开放 | 无重复 | 有容量 | 结果 |
| --- | --- | --- | --- | --- |
| 否 | — | — | — | `STUDENT_INACTIVE` |
| 是 | 否 | — | — | `COURSE_CLOSED` |
| 是 | 是 | 否 | — | `DUPLICATE_ENROLLMENT` |
| 是 | 是 | 是 | 否 | `COURSE_FULL` |
| 是 | 是 | 是 | 是 | `SUCCESS` |

## 容量边界值

| 容量 | 已选人数 | 预期结果 | 说明 |
| ---: | ---: | --- | --- |
| 2 | 1 | `SUCCESS` | 还有一个名额 |
| 2 | 2 | `COURSE_FULL` | 正常边界 |
| 2 | 3 | `COURSE_FULL` | 不允许继续新增记录，同时暴露基础数据异常 |
| 0 | 0 | `COURSE_FULL` | 没有可用名额 |
| -1 | 0 | `INVALID_CAPACITY` | 构造课程时拒绝非法基础数据 |

`DATA_ERROR`和`INVALID_CAPACITY`属于输入与基础数据保护，不改变BR-001至BR-004的核心业务含义。系统在执行BR-003前识别“已选人数大于容量”，课程容量小于0时拒绝创建课程对象。

## 共同最低保证

任何失败路径都不得新增Enrollment，不得改变当前记录数，并返回可区分的失败代码。
